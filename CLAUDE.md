# CLAUDE.md — baseballr-data Development Guide

## Repo Overview

`baseballr-data` is the R-side scraper and aggregation cache for the
[`baseballr`](https://github.com/billpetti/baseballr) R package. It pulls
NCAA baseball schedules and play-by-play from `stats.ncaa.org` via
`baseballr::ncaa_*()` helpers, persists results to disk under `ncaa/` (and
in the past, MLB Statcast monthly extracts under `statcast/`), and commits
the cumulative output back to this repo. The committed artifacts are then
uploaded as GitHub releases on
[`sportsdataverse-data`](https://github.com/sportsdataverse/sportsdataverse-data)
via the `sportsdataversedata::sportsdataverse_save()` helper baked into
each scraper script.

This repo is the authoritative cache of raw NCAA baseball payloads — the
parsing/loader layer in `baseballr` never re-hits `stats.ncaa.org`; it
reads from sportsdataverse-data releases.

## Pipeline Position

```
stats.ncaa.org --[R scrape]--> baseballr-data [HERE]
                                    | sportsdataverse_save()
                                    v
                               sportsdataverse-data (release tags)
                                    | load_ncaa_baseball_*()
                                    v
                               baseballr R package
```

The scrapers call `sportsdataversedata::sportsdataverse_save()` with the
following release tags (visible in `R/ncaa_01_*.R` and `R/ncaa_02_*.R`):

- `ncaa_baseball_schedules` — per-season unified schedule
- `ncaa_baseball_team_schedules` — per-team-season schedule fragments
- `ncaa_baseball_pbp` — per-season play-by-play
- `ncaa_baseball_teams` — team/season lookups

Downstream loaders read whatever the scrapers' `sportsdataverse_save()`
call pushes to the release tags. The in-repo
`.github/workflows/daily_ncaa_baseball.yml` is the scheduled driver (see
**Daily Cron** below); it can also be kicked by a `repository_dispatch`
event of type `daily_ncaa_baseball_data`.

## Build & Development Commands

The repo is driven by two shell entry points that wrap the R scripts:

```sh
# Daily schedule scrape (one or more seasons)
bash daily_ncaa_baseball_scraper.sh -s 2026 -e 2026 -r false

# Daily play-by-play scrape (one or more seasons)
bash daily_ncaa_baseball_pbp_scraper.sh -s 2026 -e 2026 -r false

# Or call the R scripts directly when iterating
Rscript R/ncaa_01_schedules_creation.R -s 2026 -e 2026 -r FALSE
Rscript R/ncaa_02_pbp_creation.R       -s 2026 -e 2026 -r FALSE

# Maintenance scripts (no CLI flags — run as-is, manual cadence)
Rscript R/ncaa_season_ids.R          # rebuild season_id lookup table
Rscript R/ncaa_teams_info.R          # refresh team lookup with latest division 1-3 teams
Rscript R/ncaa_util_01_schedules_conversion.R  # one-off schedule format conversion
Rscript R/ncaa_util_02_pbp_conversion.R        # one-off pbp format conversion
```

Flag semantics on the scraper scripts:

- `-s` start year, `-e` end year (inclusive integer range)
- `-r true` forces re-scrape of every team/game even if a file is on disk;
  `-r false` keeps existing CSV files and only rebuilds the unified
  per-season output from disk. `false` is the daily default.

## Output Layout

```
ncaa/
  team_schedules/{csv,json,parquet}/{year}_{team_id}.{ext}   # per-team-season scrape, one file per team
  schedules/{csv,rds,parquet}/ncaa_baseball_schedule_{year}.{ext}   # unified per-season schedule
  game_pbp/                  # per-game raw pbp scrape (intermediate)
  contest_pbp/               # per-contest pbp scrape (intermediate)
  pbp/{parquet,rds}/         # unified per-season play-by-play
  teams_info/ncaa_team_lookup.{csv,rds,parquet}              # team_id lookup, regenerated by ncaa_teams_info.R
  seasons_info/ncaa_season_id_lu.{csv,rds,parquet}           # year -> season_id map, regenerated by ncaa_season_ids.R
mlb/                         # Cached .rda lookup tables consumed by baseballr (column structures, statcast imputation,
                             #   live API empty df template, MLB teams lookup)
statcast/                    # Monthly StatcastData .parquet + .rds (2015 -> present, historical archive)
R/                           # Scraper + aggregation scripts (see below)
```

## Conventions

- **R dependencies are pinned through `lib.loc = Sys.getenv("R_LIBS")`** in every
  script. The CI environment exports `R_LIBS` to a pre-warmed library so the
  scripts skip CRAN entirely on each run. Don't add `install.packages()`
  calls — the `pacman` bootstrap at the top of each script handles the
  fallback case.
- **All scrape work is funneled through `baseballr::`**. Bug fixes to NCAA
  HTML parsing belong in the `baseballr` package, not here. This repo
  should stay thin: load `baseballr`, iterate over teams/games, persist
  output, save to a sportsdataverse-data release.
- **Proxy rotation**: `R/utils.R` exposes `get_proxy_ips()` /
  `select_proxy()` which read from env vars `PROXY_KEY`, `PROXY_PKG`,
  `PROXY_ENDPOINT`. These are required for the per-team scrape loop in
  `ncaa_01_schedules_creation.R` (NCAA aggressively rate-limits direct
  IPs). Don't commit credentials; CI provides them via Actions secrets.
  - `get_proxy_ips()` returns a pool with columns `ip`, `port_http`,
    `login`, `password`. `select_proxy()` returns the **httr2-shaped
    named list** `list(url = "http://HOST:PORT", username, password)` —
    NOT an `httr::use_proxy()` object — because baseballr's
    `request_with_proxy()` (on `BillPetti/baseballr`, the installed
    remote) routes through `httr2::req_proxy()` and spreads
    the list by name. Returning an httr v1 object makes every request
    fail with baseballr's "Invalid arguments provided".
  - `select_proxy()` hands out IPs **round-robin** (shuffle once, cycle
    the whole pool before any repeat). The scrape loops run sequentially
    (`purrr::map`) in one process, so this is a single continuous
    rotation over the whole run — minimises per-IP request rate.
- **Proxy preflight (fail-fast)**: both scrape scripts call
  `preflight_proxy_check(proxies_df)` right after `get_proxy_ips()`. It
  probes `stats.ncaa.org` through up to 5 rotating proxies and
  `cli_abort`s if all return 403/errors, so a blocked pool fails in
  seconds with a clear message instead of silently scraping nothing for
  ~30 min and crashing at assembly. **NCAA (Akamai) blocks by IP and
  403s datacenter proxies** — the scrape needs a working
  **residential/mobile** pool. A green preflight is the prerequisite for
  any successful run; if it aborts, the proxy service is the problem,
  not this repo's code.
- **Sequential scrape loops**: the scrape/aggregation loops use
  `purrr::map()` (not `furrr`/`future`) — one request at a time in a
  single process. This is intentional: NCAA rate-limits, the loops are
  sleep/I-O bound (`Sys.sleep()` per item), and sequential keeps the
  proxy round-robin and request pacing predictable. Keep the
  `Sys.sleep(5)` (schedule) / `Sys.sleep(1)` (pbp) calls inside the
  loops to space out requests. Don't reintroduce parallelism without a
  reason — it complicates rotation/pacing for little gain on a
  sleep-bound workload.
- **File-write trio**: every persisted table is written as CSV + RDS +
  Parquet. Consumers may load any of the three; don't drop one without
  updating `baseballr`'s loaders.
- **`baseballr:::make_baseballr_data()`** wraps every final tibble before
  write. It attaches `baseballr_timestamp` + a description string; do not
  bypass it.
- **Output paths are load-bearing**. Downstream `baseballr::load_ncaa_*()`
  helpers fetch from sportsdataverse-data releases whose filenames mirror
  the local layout (`ncaa_baseball_schedule_{year}.{ext}`,
  `ncaa_baseball_pbp_{year}.{ext}`, etc.). Don't rename without
  coordinating with `baseballr`.

## Daily Cron

`.github/workflows/daily_ncaa_baseball.yml` (job name **Update NCAA
Baseball Data**, `ubuntu-latest`, R release) is the in-repo driver. It
fires on three triggers:

- **`schedule`** — daily during the season (`cron: "0 11 * 2-6 *"`,
  Feb–Jun) and monthly off-season (`cron: "0 11 1 1,7-12 *"`, on the 1st).
- **`repository_dispatch`** type `daily_ncaa_baseball_data` — the
  `client_payload.commit_message` is grepped for the first/last integers
  to resolve `START_YEAR`/`END_YEAR`.
- **`workflow_dispatch`** — manual `start_year` / `end_year` / `rescrape`
  inputs.

When the year inputs are empty it defaults both to
`baseballr:::most_recent_ncaa_baseball_season()`. The job runs
`scripts/daily_ncaa_baseball_R_processor.sh -s $START_YEAR -e $END_YEAR
-r $RESCRAPE`, which loops each season calling
`R/ncaa_01_schedules_creation.R` then `R/ncaa_02_pbp_creation.R` (those
scripts publish to the sportsdataverse-data releases via
`sportsdataverse_save()`), then commits the local `ncaa/*` artifacts with
subject `"NCAA Baseball Data Update (Start: $i End: $i)"` and pushes.

Required Actions secrets: `SDV_GH_TOKEN` (cross-repo write to
sportsdataverse-data releases — the per-step `GITHUB_PAT`) plus the
`PROXY_KEY` / `PROXY_PKG` / `PROXY_ENDPOINT` proxy pool (the scrape
otherwise 403s on GitHub runner IPs).

The two **root** scripts `daily_ncaa_baseball_scraper.sh` and
`daily_ncaa_baseball_pbp_scraper.sh` are the older manual per-dataset
entry points; they commit `"NCAA Schedules update (Start: … End: …)"` /
`"NCAA PBP update (Start: … End: …)"` respectively. All three commit
subjects carry the load-bearing `(Start: YYYY End: YYYY)` shape — keep it
intact.

## Project-Specific Gotchas

- `baseballr::most_recent_ncaa_baseball_season()` is called both in
  `bash_functions.sh` (to resolve `RESULT`) and as the default
  `-s`/`-e` value in every R script. If `baseballr` is not on the R
  library path, the optparse defaults will error before getopts even
  parses. Always export `R_LIBS` before running the shell entry point.
- The MLB Statcast extracts under `statcast/` are **historical** — they
  pre-date the current scrape pipeline and are kept as a static archive
  for `baseballr::scrape_statcast_savant()` consumers. Do not extend the
  daily flow to overwrite them without confirming the downstream loader
  contract.
- `baseballr` is installed from `BillPetti/baseballr` (bare — the default
  `master` branch) in `DESCRIPTION` Remotes and the workflow
  `extra-packages`. The 2.0.0 release merged the former
  `development_branch` into `master` (httr2 migration, NCAA/proxy fixes,
  and the drop of the now-archived `qs` dependency that previously broke
  `setup-r-dependencies` resolution), so the bare remote resolves cleanly.
  Do **not** re-pin to a branch.
- `make_baseballr_data()` lives in the `baseballr` package's non-exported
  namespace and is referenced via `baseballr:::` (triple colon). Same for
  `rbindlist_with_attrs()` and `most_recent_ncaa_baseball_season()`. If
  `baseballr` is upgraded and renames any of these, the scrapers break
  silently — pin the upstream `baseballr` version in CI.

## Commit Convention

This repo predates the SportsDataverse Conventional Commits convention.
The two daily shell scripts produce hardcoded subject lines that are
load-bearing for any downstream parsing:

```
NCAA Schedules update (Start: 2026 End: 2026)
NCAA PBP update (Start: 2026 End: 2026)
```

Keep the `(Start: YYYY End: YYYY)` suffix intact on automated commits.

For human-authored commits, prefer [Conventional Commits](https://www.conventionalcommits.org/):

```
feat(scrape): add NCAA Tournament fallback IDs to ncaa_01_schedules_creation.R
fix(scrape): handle 503s in ncaa_02_pbp_creation.R without aborting the season loop
chore(deps): bump baseballr pin in the CI library
```

**Important: Never include AI agents or assistants (e.g., Claude, Copilot, Cursor, GPT, Gemini) as co-authors on commits.** Omit all `Co-Authored-By` trailers referencing AI tools. This applies whether the change was generated, refactored, or reviewed with AI assistance — the human author is the sole attributable contributor.
